    58→
    59→### Формат файла (v1, менять только с повышением версии)
    60→
    61→```
    62→magic "OPVAULT1"(8) | version u16 | kdf_id u8=1 | m_cost u32 | t_cost u32 | p_cost u32
    63→| salt(16) | nonce(24) | ciphertext
    64→```
    65→
    66→- Ключ: `Argon2id(password, salt, m=65536 КиБ, t=3, p=1) -> 32 байта`.
    67→- Шифр: XChaCha20-Poly1305, nonce новый при каждой записи.
    68→- AAD: весь заголовок (0..63), поэтому параметры KDF и соль защищены от подмены.
    69→- Полезная нагрузка: JSON `VaultData { schema: 3, items: [...] }`.
    70→- Запись: временный файл в том же каталоге → `sync_all` → атомарное переименование.
    71→
    72→### Сайдкар Windows Hello (v1, рядом с хранилищем)
    73→
    74→```
    75→magic "OPHELLO1"(8) | version u16=1 | nonce(12) | wrapped_key(48) | dpapi_blob(..)
    76→```
    77→
    78→- `wrapped_key` = AES-256-GCM(ключ обёртки, ключ хранилища); AAD — магия, версия, nonce.
    79→- Ключ обёртки в открытом виде не хранится: `dpapi_blob` — он же под DPAPI (область
    80→  пользователя), ядро его не интерпретирует.
    81→- Путь: `<путь-хранилища>.hello`. В git не попадает (`*.hello` в `.gitignore`).
    82→- Смена мастер-пароля и `Vault::create` по старому пути удаляют сайдкар.
    83→
    84→### Модель
    85→
    86→```rust
    87→ItemKind { Login, SecureNote, Card, BankAccount, Passport, ForeignPassport, Snils,
    88→           Inn, DriverLicense, MedicalPolicy, DigitalSignature, ApiKey, Wifi, Pin,
    89→           Insurance, Property, Health, Vehicle }   // 18 типов, serde snake_case
    90→
    91→Item { id: Uuid, kind, title, username, password, url, notes,
    92→       tags: Vec<String>, fields: Vec<Field>, created_at, updated_at }
    93→
    94→Field { label: String, value: String, sensitive: bool }
    95→```
    96→
    97→- `ItemKind::template()` — готовые поля для типа.
    98→- `Item::with_template(kind, title)` — запись с шаблоном.
    99→- `sensitive` поля маскируются, не индексируются поиском и зануляются в `Drop`.
   100→- Пароль и заметки тоже зануляются в `Drop` у `Item`.

   102→## 4. Что уже работает
   103→
   104→- Создание и открытие хранилища, смена мастер-пароля.
   105→- Логины и защищённые заметки, поиск по видимым полям.
   106→- Генератор паролей (длина, классы, без `Il1O0o`) и запоминаемые фразы
   107→  (3–8 слов из словаря 1045 русских / 851 английское слово, 0–4 цифры,
   108→  разделитель, заглавные); честная энтропия и вердикт; окно «Генератор».
   109→- Быстрая вставка: скопированный логин и пароль («логин пароль»,
   110→  login:password, «сайт логин пароль», https://ivan:secret@site.ru,
   111→  строки «Логин: …»/«Пароль: …») разбираются в готовую запись
   112→  с предпросмотром и правкой полей.
   113→- Осмысленные описания: для всех 18 типов, секреты не попадают (у карты —
   114→  маска •••• 1234); кнопка «Описания» — всем записям без заметок разом,
   115→  кнопка «Описать» — одной записи; описание видно в списке и в поиске.
   116→- Индикатор стойкости пароля (биты + цветной вердикт) в карточке и диалоге записи.
   117→- Карты и банковские счета; 14 шаблонов документов и ключей (всего 18 типов).
   118→- Импорт: Bitwarden JSON, Bitwarden CSV, 1Password CSV, Яндекс Браузер CSV
   119→  и обычный CSV; дубликаты пропускаются.
   120→- Буфер обмена с автоочисткой через 30 секунд.
   121→- Автоблокировка через 5 минут бездействия.
   122→- Светлая и тёмная тема, выбор сохраняется в `%APPDATA%\Hranitel\settings.txt`.
   123→- Вход через Windows Hello: обёртка ключа + DPAPI + подтверждение присутствия;
   124→  кнопки «Войти через Windows Hello» и «Hello: включён/выключен».
   125→- Встроенная справка: F1 (запасной вариант — Ctrl+H) в любом месте окна, 23 раздела
   126→  по всем функциям; кнопки «Справка (F1)» на экране входа и в тулбаре.
   127→- Коды TOTP в карточке (base32 и otpauth://, SHA1/256/512) с обратным отсчётом и копированием.
   128→- Аудит: повторяющиеся и короткие пароли, давние записи, истекающие сроки (90 дней).
   129→- Экспорт JSON (полный) и CSV (Bitwarden) с подтверждением мастер-пароля.
   130→- Смена мастер-пароля в окне (кнопка «Пароль»).
   131→- Горячие клавиши Ctrl+F / Ctrl+C / Esc; версия в заголовке окна.
   132→- Автоввод в программы: горячая клавиша по умолчанию Ctrl+Alt+P (меняется
   133→  в «Настройках» нажатием, хранится в settings.txt), печатает логин, Tab, пароль,
   134→  Enter в активное окно; работает из свёрнутого окна.
   135→- Категории над списком (Все/Логины/Карты/Счета/Заметки/Документы/Ключи) с числами.
   136→- Несколько сайтов у записи (url + urls): сайт и кабинеты в одной записи, матчинг
   137→  по базовому домену (lk.domclick.ru = domclick.ru, github.example.com ≠ github.com).
   138→- Быстрый доступ: Ctrl+Shift+Space (меняется) поднимает из любого окна палитру
   139→  с фильтром; записи, подходящие окну по домену/имени сайта, — наверху; Enter
   140→  возвращает фокус целевому окну и печатает туда логин и пароль; Ctrl+C — пароль.
   141→- Автозаполнение в браузере (Chrome/Edge, модель KeePassXC): расширение +
   142→  browser-host + именованный канал; иконка в поле, список по клику, пароль по id
   143→  только своему сайту, сохранение/обновление с подтверждением в приложении,

   230→## 6. Грабли (проверено на практике)
   231→
   232→**egui/eframe 0.37**
   233→- `App::update` больше нет: реализуется `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut Frame)`.
   234→- `TopBottomPanel`/`SidePanel` заменены на `egui::Panel::bottom(...)`; `CentralPanel::show(ui, ...)`.
   235→- Вложенные панели внутри `Ui` легко получают нулевую высоту — в этом проекте вместо них
   236→  фиксированная область контента + строка статуса.
   237→- `clear_color` надо переопределять, иначе eframe заливает окно чёрным и светлая тема «не работает».
   238→- Два `ScrollArea` без `id_salt` дают предупреждение о дублирующемся ID.
   239→- У `Slider` в 0.37 нет метода `clamp_to_range` — не пытаться, значение и так
   240→  остаётся в диапазоне при перетаскивании.
   241→- Закрыть окно изнутри замыкания `.show(...)` нельзя: `open` уже занят мут-займом
   242→  из `.open(&mut open)` → E0499. Решение — локальный флаг (`cancel = true`),
   243→  а действия по нему — после `.show()`.
   244→- Вызов метода приложения внутри замыкания кадра с ссылкой на его же поле даёт
   245→  E0502 (`self.copy(&self.gen_result, …)`): сначала `let result = self.gen_result.clone();`.
   246→- Headless-тест кадра: `ctx.run_ui(...)` возвращает `FullOutput`, у которого нужно
   247→  вызвать `textures_delta.clear()`, иначе epaint срабатывает на debug_assert при Drop.
   248→
   249→**Крейты**
   250→- `argon2 0.6`: `Params::new(m, t, p, Some(32))`, `hash_password_into`.
   251→- `chacha20poly1305 0.11`: `Aead::encrypt(&nonce, Payload { msg, aad })`.
   252→- `rand 0.10`: `rand::fill`, `rand::rng()`, трейт `RngExt`.
   253→- `rpassword 1.0`: функции `prompt_password_stderr`, старой `prompt_password` нет.
   254→- edition 2024: `gen` — зарезервированное слово, функцию пришлось назвать `generate_cmd`.
   255→- clippy в edition 2024 ругается на вложенный `if let` (`collapsible_if`) — склеивать
   256→  в один `if … && let …`, а присваивание полей после `Default::default()` — на
   257→  `field_reassign_with_default`, инициализировать структурным синтаксисом.
   258→
   259→**Окружение**
   260→- В оболочке AutoClaw переменные `APPDATA` и `LOCALAPPDATA` пустые. Приложение и скрипты
   261→  должны собирать путь от `USERPROFILE`. В обычной сессии Windows всё работает штатно.
   262→- GitHub CLI установлен портативно: `%USERPROFILE%\AppData\Local\GitHubCLI\bin`, добавлен в PATH.
   263→- `git push` работает через Windows Credential Manager (`credential.helper=manager`).
   264→- Токены, которые передавались в чате, считаются скомпрометированными — их нужно отозвать
   265→  в GitHub → Settings → Developer settings → Personal access tokens.
   266→- При сборке в фоне проверяйте mtime бинарника: фильтрация вывода иногда скрывает ошибки.
   267→
   268→**Windows Hello / DPAPI**
   269→- `windows 0.62`: для DPAPI берём классический Win32 `CryptProtectData`/`CryptUnprotectData`
   270→  (`Win32_Security_Cryptography`), а не WinRT `DataProtectionProvider`: синхронно, без квартиры.
   271→- `UserConsentVerifier::RequestVerificationAsync` — WinRT, возвращает `IAsyncOperation`;
   272→  блокирующее ожидание — `.join()` (крейт `windows-future`): ждёт событие и не прокачивает
   273→  сообщения, поэтому вызывать только из фонового потока, не из UI-потока egui.
   274→- На рабочем потоке перед WinRT нужен `CoInitializeEx(None, COINIT_MULTITHREADED)`
   275→  (`Win32_System_Com`); результат можно игнорировать.
   276→- DPAPI-блоб привязан к учётной записи и машине: копия сайдкара на другом ПК не
   277→  разворачивается — это ожидаемо, а не баг.
   278→- `aes-gcm 0.11` (aead 0.6): nonce — `Nonce<U12>` из `aes_gcm::aead::consts::U12`,
   279→  `encrypt`/`decrypt` принимают `&Nonce`, ключ — `new_from_slice`.
   280→- `hmac 0.13` / `sha1 0.11` / `sha2 0.11` (digest 0.11): `Hmac<D>::new_from_slice`,
   281→  `update`, `finalize().into_bytes()`. Секреты TOTP — через base32 (`data-encoding`).
   282→- `time 0.3`: `Date::parse` с `format_description!`; `to_julian_day()` возвращает i32
   283→  (в разнице дней приводить к i64); `Month::length(year)` — длина месяца для срока карты.
   284→- `cargo test -p vault-win` действительно вызывает DPAPI и проверяет раунд-трип —
   285→  это единственный тест системных вызовов без GUI.
   286→- **Копия файла в Проводнике — это не текст**: в буфере лежит список файлов
   287→  (CF_HDROP), поэтому Ctrl+V в поле пути ничего не даёт. В 0.7.1 это решено
   288→  кнопкой «Выбрать файл…» (`GetOpenFileNameW`), кнопкой «Вставить путь»
   289→  (`GetClipboardData(CF_HDROP)` + `DragQueryFileW`) и перетаскиванием файла
   290→  в окно (egui `raw.dropped_files`, путь берётся через `file.path()`).
   291→- **Релизная сборка без консоли**: `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`
   292→  в `main.rs`. Без него рядом с окном открывается консоль и забирает фокус с клавишами
   293→  (именно так «не работал» F1). В debug-сборке консоль остаётся для логов.
   294→- Системные диалоги `GetOpenFileNameW`/`GetSaveFileNameW` блокируют UI-поток —
   295→  это нормально для модального окна; после возврата egui продолжает кадры.
   296→- **Автоввод живёт на своём потоке**: `RegisterHotKey(None, ...)` + `GetMessageW`
   297→  в отдельном std::thread (см. autotype.rs). Когда окно свёрнуто, eframe не вызывает
   298→  `ui()`, поэтому печатать из UI-кадра нельзя — печать идёт в потоке горячей клавиши,
   299→  а данные для неё лежат в `Mutex<Option<Credentials>>` (пароль — `Zeroizing<String>`).
   300→- `SendKeys` в PowerShell НЕ вызывает зарегистрированные hotkey — для проверки
   301→  использовать `keybd_event`/`SendInput`. Ввод идёт `SendInput` + `KEYEVENTF_UNICODE`,
   302→  иначе кириллица и нестандартные раскладки не работают; в окна от администратора
   303→  ввод блокируется UIPI (SendInput вернёт меньше событий).
   304→- **Горячая клавиша перерегистрируется на лету**: `RegisterHotKey`/`UnregisterHotKey`
   305→  работают только на своём потоке, поэтому перебиндинг идёт через `PostThreadMessageW`
   306→  с `WM_APP+1` в поток клавиши (autotype.rs), а поток отвечает через канал — UI
   307→  точно знает, встала ли комбинация. Если новая занята, старая возвращается на место;
   308→  признак «работает» читается из `READY` каждый кадр, поэтому подсказка не врёт.
   309→- **Запись сочетания в «Настройках»** берёт события `egui::Event::Key` и переводит
   310→  `egui::Key` в виртуальный код Win32 только для букв, цифр и F1–F20. Пока идёт
   311→  запись, F1/Ctrl+F/Esc/поиск не перехватываются, иначе сочетание нельзя было бы ввести.
   312→- **Два экземпляра — источник путаницы**: RegisterHotKey держит только первая копия,
   313→  а печатает та запись, что выбрана в ней. С 0.6.4 второй экземпляр берёт мьютекс
   314→  `Hranitel.SingleInstance`, показывает MessageBox и выходит. Старые сборки (≤0.6.3)
   315→  мьютекс не берут: если запущены и старая, и новая, Ctrl+Alt+P отработает старая.
   316→  `CreateMutexW` требует `SetLastError(0)` перед вызовом — иначе `GetLastError`
   317→  отдаёт сталый код и ложное срабатывание.
   318→- **Дистрибутив в `dist/` собирается вручную**: копия `vault-win.exe`, `vault-cli.exe`,
   319→  README и `docs` в `dist\Hranitel-<версия>-win64`, затем `Compress-Archive`. Старые пакеты
   320→  не удаляются; если пользователь запускает вчерашний exe, он не видит новых функций.
   321→  После изменений всегда пересобирайте пакет и давайте путь к самому свежему.
   322→
   323→**Не коммитить**: `target`, `dist`, `*.opvault`, `*.vault`, `*.hello`, папку `NVIDIA Corporation`.

   325→## 7. Ограничения текущей версии
   326→
   327→- Нет синхронизации между устройствами и мобильного клиента.
   328→- Расширение браузера: Chrome/Edge; Firefox (формат allowed_extensions) не
   329→  поддерживается. Иконки в трее и passkeys нет.
   330→- Windows Hello: только подтверждение присутствия, без TPM-привязки; доступность
   331→  Hello проверяется при первом входе, а не при включении опции.
   332→- TOTP хранится как скрытое поле и может быть раскрыт кнопкой «Показать», как любое
   333→  скрытое поле; отдельного «защищённого» режима для секрета нет.
   334→- 1Password 1PUX (архив) не читается, только CSV.
   335→- CSV-экспорт теряет типы записей (документы уходят как логины); для полной копии — JSON.
   336→- Автоввод: только логин/пароль выбранной записи и фиксированная последовательность
   337→  (логин → Tab → пароль → Enter); отдельных сценариев под конкретные окна нет.
   338→- Быстрый доступ и автоввод ищут главное окно по заголовку «Хранитель…» —
   339→  не переименовывайте APP_TITLE без правки MAIN_TITLE_PREFIX в autotype.rs.
   340→- Быстрая вставка понимает перечисленные форматы; пароль с пробелами внутри —
   341→  только через строку «Пароль: …», иначе он делится на токены.
   342→- Карты из Bitwarden CSV приходят без реквизитов (в CSV их нет).
   343→- Нет напоминаний об истечении срока документов и карт.
   344→- Внешнего аудита не было.

   520→### 0.8.2: путь к хранилищу и надёжный автоввод
   521→
   522→- При открытии или создании хранилища путь пишется в `settings.txt` (`path=...`)
   523→  и подставляется в поле при следующем запуске — длинный путь не нужно вводить заново.
   524→- **Автоввод больше не теряет символы**: WM_HOTKEY приходит, когда Ctrl/Alt ещё зажаты,
   525→  и SendInput в этот момент отдавал текст как сочетания — в чужом окне не появлялось
   526→  ничего, хотя приложение сообщало «введено». Теперь перед печатью ждём отпускания
   527→  Ctrl/Alt/Shift/Win (до 1,2 с) и только потом печатаем (autotype.rs).
   528→
   529→### 0.8.1: смена сочетания без сюрпризов
   530→
   531→- В «Настройках» сочетание записывается нажатием: «Записать сочетание» → нажать
   532→  комбинацию целиком; текстовый ввод остался как запасной.
   533→- Поток автоввода отвечает на перерегистрацию: если комбинация занята, остаётся
   534→  прежняя, а диалог показывает причину (раньше старая снималась и автоввод
   535→  оставался без клавиши).
   536→- Признак «клавиша работает» (`autotype::is_ready()`) читается каждый кадр —
   537→  подсказка в правом нижнем углу обновляется сразу.

   539→  зависит от кадров, поэтому работает и из свёрнутого окна.
   540→- Окно-мишень показывает сочетание из settings.txt (по умолчанию Ctrl+Alt+P),
