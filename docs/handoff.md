# Передача проекта «Хранитель» (handoff)

Документ для агента, который продолжит работу. Всё, что нужно знать, чтобы
собрать, проверить и не наступить на уже пройденные грабли.

Дата: 18 ноября 2026. Версия: **0.13.0**.

## 1. Что это

Локальный менеджер паролей для Windows. Один зашифрованный файл, без сети и аккаунтов.
Ядро на Rust, CLI и оконный клиент на egui/eframe.

Расположение: `E:\Work\VSC\POSPassword`
Репозиторий: https://github.com/reznikov73/POSPassword (приватный, ветка `main`)
Последний коммит на момент передачи: `dc1fe09`

## 2. Быстрый старт

```powershell
cd E:\Work\VSC\POSPassword
cargo test --workspace                       # ~160 тестов, все должны пройти
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release -p vault-win
.\target\release\vault-win.exe
cargo build --release -p browser-host        # родной хост для расширения
```

CI (`.github/workflows/ci.yml`) прогоняет то же на windows-latest и
ubuntu-latest (ядро + кросс-таргет-проверка vault-win) при каждом пуше.

Если проверка идёт не на Windows, а на Linux: `windows-future 0.3.2` не собирается
под линукс-таргет, поэтому vault-win проверяется кросс-таргетом:
`rustup target add x86_64-pc-windows-msvc` и
`cargo clippy -p vault-win --target x86_64-pc-windows-msvc --all-targets -- -D warnings`
(для check/clippy линкер не нужен). Так и делалось для 0.9.0.

В VS Code: `Ctrl+Shift+B` — сборка, `F5` — отладка, `Ctrl+Shift+P` → «Задачи: Выполнить задачу» —
список задач на русском. Расширения уже установлены.

### Формат файла (v1, менять только с повышением версии)

```
magic "OPVAULT1"(8) | version u16 | kdf_id u8=1 | m_cost u32 | t_cost u32 | p_cost u32
| salt(16) | nonce(24) | ciphertext
```

- Ключ: `Argon2id(password, salt, m=65536 КиБ, t=3, p=1) -> 32 байта`.
- Шифр: XChaCha20-Poly1305, nonce новый при каждой записи.
- AAD: весь заголовок (0..63), поэтому параметры KDF и соль защищены от подмены.
- Полезная нагрузка: JSON `VaultData { schema: 4, items: [...] }`.
  Schema 3 (0.12.x) читается без миграций: новые поля `favorite` и
  `password_history` идут с `serde(default)`. Старое приложение 0.12
  откроет новый файл, но при сохранении из него новые поля теряются —
  предупреждение в docs/transfer.md и README.
- Запись: временный файл в том же каталоге → `sync_all` → атомарное переименование.

### Сайдкар Windows Hello (v1, рядом с хранилищем)

```
magic "OPHELLO1"(8) | version u16=1 | nonce(12) | wrapped_key(48) | dpapi_blob(..)
```

- `wrapped_key` = AES-256-GCM(ключ обёртки, ключ хранилища); AAD — магия, версия, nonce.
- Ключ обёртки в открытом виде не хранится: `dpapi_blob` — он же под DPAPI (область
  пользователя), ядро его не интерпретирует.
- Путь: `<путь-хранилища>.hello`. В git не попадает (`*.hello` в `.gitignore`).
- Смена мастер-пароля и `Vault::create` по старому пути удаляют сайдкар.

### Модель

```rust
ItemKind { Login, SecureNote, Card, BankAccount, Passport, ForeignPassport, Snils,
           Inn, DriverLicense, MedicalPolicy, DigitalSignature, ApiKey, Wifi, Pin,
           Insurance, Property, Health, Vehicle }   // 18 типов, serde snake_case

Item { id: Uuid, kind, title, username, password, url, notes,
       tags: Vec<String>, fields: Vec<Field>, created_at, updated_at }

Field { label: String, value: String, sensitive: bool }
```

- `ItemKind::template()` — готовые поля для типа.
- `Item::with_template(kind, title)` — запись с шаблоном.
- `sensitive` поля маскируются, не индексируются поиском и зануляются в `Drop`.
- Пароль и заметки тоже зануляются в `Drop` у `Item`.

## 4. Что уже работает

- Создание и открытие хранилища, смена мастер-пароля.
- Логины и защищённые заметки, поиск по видимым полям.
- Генератор паролей (длина, классы, без `Il1O0o`) и запоминаемые фразы
  (3–8 слов из словаря 1045 русских / 851 английское слово, 0–4 цифры,
  разделитель, заглавные); честная энтропия и вердикт; окно «Генератор».
- Быстрая вставка: скопированный логин и пароль («логин пароль»,
  login:password, «сайт логин пароль», https://ivan:secret@site.ru,
  строки «Логин: …»/«Пароль: …») разбираются в готовую запись
  с предпросмотром и правкой полей.
- Осмысленные описания: для всех 18 типов, секреты не попадают (у карты —
  маска •••• 1234); кнопка «Описания» — всем записям без заметок разом,
  кнопка «Описать» — одной записи; описание видно в списке и в поиске.
- Индикатор стойкости пароля (биты + цветной вердикт) в карточке и диалоге записи.
- Карты и банковские счета; 14 шаблонов документов и ключей (всего 18 типов).
- Импорт: Bitwarden JSON, Bitwarden CSV, 1Password CSV, Яндекс Браузер CSV
  и обычный CSV; дубликаты пропускаются.
- Буфер обмена с автоочисткой через 30 секунд.
- Автоблокировка через 5 минут бездействия.
- Светлая и тёмная тема, выбор сохраняется в `%APPDATA%\Hranitel\settings.txt`.
- Вход через Windows Hello: обёртка ключа + DPAPI + подтверждение присутствия;
  кнопки «Войти через Windows Hello» и «Hello: включён/выключен».
- Встроенная справка: F1 (запасной вариант — Ctrl+H) в любом месте окна, 23 раздела
  по всем функциям; кнопки «Справка (F1)» на экране входа и в тулбаре.
- Коды TOTP в карточке (base32 и otpauth://, SHA1/256/512) с обратным отсчётом и копированием.
- Аудит: повторяющиеся и короткие пароли, давние записи, истекающие сроки (90 дней).
- Экспорт JSON (полный) и CSV (Bitwarden) с подтверждением мастер-пароля.
- Смена мастер-пароля в окне (кнопка «Пароль»).
- Горячие клавиши Ctrl+F / Ctrl+C / Esc; версия в заголовке окна.
- Автоввод в программы: горячая клавиша по умолчанию Ctrl+Alt+P (меняется
  в «Настройках» нажатием, хранится в settings.txt), печатает логин, Tab, пароль,
  Enter в активное окно; работает из свёрнутого окна.
- Категории над списком (Все/Логины/Карты/Счета/Заметки/Документы/Ключи) с числами.
- Несколько сайтов у записи (url + urls): сайт и кабинеты в одной записи, матчинг
  по базовому домену (lk.domclick.ru = domclick.ru, github.example.com ≠ github.com).
- Быстрый доступ: Ctrl+Shift+Space (меняется) поднимает из любого окна палитру
  с фильтром; записи, подходящие окну по домену/имени сайта, — наверху; Enter
  возвращает фокус целевому окну и печатает туда логин и пароль; Ctrl+C — пароль.
- Автозаполнение в браузере (Chrome/Edge, модель KeePassXC): расширение +
  browser-host + именованный канал; иконка в поле, список по клику, пароль по id
  только своему сайту, сохранение/обновление с подтверждением в приложении,
  разрешение по доменам (browser-sites.txt), генератор на странице;
  подробности — docs/browser.md.
- Контрастная тема: почти чёрный текст, рамки кнопок и полей.
- После открытия хранилища первая запись выбирается сама; в углу видно
  «Автоввод: <запись>», причины отказа показываются текстом сверху.
- Интерфейс по макету A: тулбар одной строкой (слева действия, справа
  «Аудит · N» янтарный/зелёный, Hello, ⚙-меню, Справка), чипсы категорий
  со счётчиками и «★ Избранное» (Ctrl+1..8), строки списка с аватаром
  типа и бейджами (TOTP, срок, ★), контекстное меню ПКМ.
- Карточка: звезда избранного, TOTP-блок «XXX XXX» с кольцом отсчёта
  (секрет в карточке не показывается), шкала стойкости из 5 сегментов,
  сайты и теги чипсами, даты, «Ввести в окно · 3 с» внизу.
- Избранное (Ф-1) и история пароля ≤5 версий с «Сделать текущим» (Ф-2,
  И-5); Ctrl+T в палитре копирует код TOTP (Ф-4).
- Undo удаления (И-6): toast «Вернуть» 10 секунд, запись возвращается
  с теми же id и датами (`Vault::restore`); буфер сбрасывается при lock.
- Окно помнит размер и позицию (size=, pos=), clamp к экрану; скрытое
  в трей (−32000) и развёрнутое состояния не портят значения (И-7).
- Напоминание при разблокировке об истекающих ≤30 дн / просроченных (И-9);
  порог мягче аудита (90 дн) — оба задокументированы.
- Полный PSL (приватные зоны включены) и punycode IDN (Б-1, Б-2):
  userA.github.io ≠ userB.github.io, кириллические омографы не совпадают.
- Аудит+ (Ф-3): пароль = логин, имя сайта в пароле, словарь топ-10 000
  (SecLists xato-net, встроен); индикатор стойкости мастер-пароля (Б-5).
- Пресеты Argon2 (Б-6): Стандарт/Усиленный/Максимальный с замером времени
  в фоне; параметры в заголовке, апгрейд при смене пароля.
- Резервные копии (Ф-5): `<файл>.bak` при каждом save + ручная копия
  vault-ГГГГ-ММ-ДД.opvault из меню ⚙ (системный диалог).
- Лок файла (Ф-6, модель KeePass): сайдкар `<файл>.lock` (fs4), GUI держит
  от открытия до блокировки, CLI — на время команды; «занято» — внятная
  ошибка, упавший процесс лок не вешает. Смена мастер-пароля проверяет
  текущий пароль по ключу (`Vault::verify_password`), а не повторным open.
- DACL канала моста — текущий пользователь + SYSTEM (Б-3а); PID и образ
  подключившегося — в журнал (диагностика, не граница).
- Буфер обмена чистится при блокировке; App.clipboard и Draft.password —
  Zeroizing/Drop (Б-4). Hello включается только после фоновой проверки
  доступности (Б-7).
- Лог-файл %APPDATA%\Hranitel\log.txt, ротация 1 МиБ × 3 (Т-4); только
  действия, уровни, PID и образы — названия записей и секреты не пишутся.
- CI (Т-2): windows (fmt/clippy/test/cargo-audit) + ubuntu (ядро и
  кросс-таргет vault-win); release по тегу v* собирает dist + setup.exe.
- CLI со всеми операциями (в gen появился --phrase).
- ~160 тестов: ядро и модульные, обёртка Hello, импорт, шаблоны, TOTP,
  аудит+ (включая словарь и эвристики), экспорт, описания, фразы,
  разбор вставки, PSL/IDN-векторы (bank.co.il ≠ evil.co.il,
  userA.github.io ≠ userB.github.io, омографы), история пароля (≤5,
  восстановление, round-trip), резервные копии (.bak побайтово),
  лок файла (в два процесса), пресеты KDF, golden-совместимость 0.12.x
  (замороженные фикстуры), справка, автоввод, буфер, окно-мишень,
  протокол моста, рамка Native Messaging, дата в имени копии,
  геометрия настроек. На Linux проходят ~140 (всё, кроме vault-win),
  остальное проверено кросс-таргетом и в CI на windows-latest.

10. Оставить окно на 5 минут → блокировка.

12. «Заблокировать» → на экране входа появилась кнопка «Войти через Windows Hello» →
    подтвердить Hello → хранилище открыто, мастер-пароль не спрашивался.
13. Отменить запрос Hello (Esc) → появилось сообщение с предложением ввести пароль;

14. Сменить мастер-пароль через CLI → сайдкар исчез, вход через Hello недоступен,

15. В любом месте окна нажать F1 (или Ctrl+H) → открылась справка со всеми

    «Справка (F1)» на входе и в тулбаре.
16. Импортировать запись с TOTP → в карточке виден код и обратный отсчёт; «Копировать»
    кладёт код в буфер.
17. Добавить пару записей с одинаковым паролем и карту со сроком «12/27» → «Аудит»
    показывает повторы и срок; клик по находке открывает запись.
18. «Экспорт…» → JSON с подтверждением пароля → файл создан; импорт этого файла
    в новое хранилище возвращает записи.
19. «Пароль» → смена мастер-пароля → старый не подходит, новый работает, вход через
    Hello исчез (сайдкар удалён).
20. Автоввод: после открытия хранилища первая запись выбрана автоматически;
    щёлкнуть в поле входа другой программы, нажать Ctrl+Alt+P → логин, Tab, пароль,
    Enter (проверено на тестовом окне, включая кириллицу в пароле). Если активно окно
    «Хранителя» — ввод не выполняется, сверху появляется сообщение с причиной.
21. Кнопка «Ввести в окно» в карточке: отсчёт 3 секунды → ввод в активное окно
    (ввод запускает отдельный поток, поэтому работает и из свёрнутого окна).
    В правом нижнем углу всегда видна подсказка «Ctrl+Alt+P — автоввод»
    (или «автоввод недоступен», если комбинация занята другой программой).
22. `tools\login-probe.exe` (в пакете: `tools\login-probe.exe`): окно с полями
    «Логин» и «Пароль»; подсказка берёт сочетание из настроек (по умолчанию Ctrl+Alt+P);
    нажатие в нём → в блоке «Что пришло в поля» видно логин и пароль, есть пометка
    про не-ASCII символы.
23. Запустить вторую копию `vault-win.exe` → появляется окно ««Хранитель» уже
    запущен в другом окне» и второй процесс завершается.
24. Импорт выгрузки Яндекса (`url,username,password,comment,tags`) → записи создаются
    с названием из адреса сайта; повторный импорт того же файла даёт только дубликаты.
25. «Импорт…» → «Выбрать файл…» открывает системный диалог с фильтром CSV/JSON;
    «Вставить путь» берёт файл, скопированный в Проводнике; файл можно перетащить в окно.
26. «Настройки» → «Записать сочетание» → нажать `Ctrl+Shift+F2`: диалог закрылся,
    в строке состояния новая комбинация, старое сочетание больше не срабатывает.
    Если записать заведомо занятую комбинацию, остаётся прежняя, а в диалоге —
    причина.
27. «Генератор» → режим «Запоминаемая фраза» → «Корабль-Мандарин-…-42», под
    образцом энтропия и вердикт; смена числа слов/цифр сразу меняет образец;
    «Копировать» кладёт фразу в буфер и она исчезает через 30 секунд.
    В диалоге записи «Фраза» и «Случайный» пользуются настройками из генератора.
28. «Быстрая вставка» → скопировать строку `mail.ru ivan Pa$$w0rd` → «Взять из
    буфера обмена» → поля заполнены (Название mail.ru, Логин ivan, Пароль
    скрыт точками) → «Создать запись» → запись в списке с описанием в заметках.
    То же для `https://ivan:secret@mail.ru/` и строк «Логин: … Пароль: …».

## 6. Грабли (проверено на практике)

**egui/eframe 0.37**
- `App::update` больше нет: реализуется `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut Frame)`.
- `TopBottomPanel`/`SidePanel` заменены на `egui::Panel::bottom(...)`; `CentralPanel::show(ui, ...)`.
- Вложенные панели внутри `Ui` легко получают нулевую высоту — в этом проекте вместо них
  фиксированная область контента + строка статуса.
- `clear_color` надо переопределять, иначе eframe заливает окно чёрным и светлая тема «не работает».
- Два `ScrollArea` без `id_salt` дают предупреждение о дублирующемся ID.
- У `Slider` в 0.37 нет метода `clamp_to_range` — не пытаться, значение и так
  остаётся в диапазоне при перетаскивании.
- Закрыть окно изнутри замыкания `.show(...)` нельзя: `open` уже занят мут-займом
  из `.open(&mut open)` → E0499. Решение — локальный флаг (`cancel = true`),
  а действия по нему — после `.show()`.
- Вызов метода приложения внутри замыкания кадра с ссылкой на его же поле даёт
  E0502 (`self.copy(&self.gen_result, …)`): сначала `let result = self.gen_result.clone();`.
- Headless-тест кадра: `ctx.run_ui(...)` возвращает `FullOutput`, у которого нужно
  вызвать `textures_delta.clear()`, иначе epaint срабатывает на debug_assert при Drop.

**Крейты**
- `argon2 0.6`: `Params::new(m, t, p, Some(32))`, `hash_password_into`.
- `chacha20poly1305 0.11`: `Aead::encrypt(&nonce, Payload { msg, aad })`.
- `rand 0.10`: `rand::fill`, `rand::rng()`, трейт `RngExt`.
- `rpassword 1.0`: функции `prompt_password_stderr`, старой `prompt_password` нет.
- edition 2024: `gen` — зарезервированное слово, функцию пришлось назвать `generate_cmd`.
- clippy в edition 2024 ругается на вложенный `if let` (`collapsible_if`) — склеивать
  в один `if … && let …`, а присваивание полей после `Default::default()` — на
  `field_reassign_with_default`, инициализировать структурным синтаксисом.

**Окружение**
- В оболочке AutoClaw переменные `APPDATA` и `LOCALAPPDATA` пустые. Приложение и скрипты
  должны собирать путь от `USERPROFILE`. В обычной сессии Windows всё работает штатно.
- GitHub CLI установлен портативно: `%USERPROFILE%\AppData\Local\GitHubCLI\bin`, добавлен в PATH.
- `git push` работает через Windows Credential Manager (`credential.helper=manager`).
- Токены, которые передавались в чате, считаются скомпрометированными — их нужно отозвать
  в GitHub → Settings → Developer settings → Personal access tokens.
- При сборке в фоне проверяйте mtime бинарника: фильтрация вывода иногда скрывает ошибки.

**Windows Hello / DPAPI**
- `windows 0.62`: для DPAPI берём классический Win32 `CryptProtectData`/`CryptUnprotectData`
  (`Win32_Security_Cryptography`), а не WinRT `DataProtectionProvider`: синхронно, без квартиры.
- `UserConsentVerifier::RequestVerificationAsync` — WinRT, возвращает `IAsyncOperation`;
  блокирующее ожидание — `.join()` (крейт `windows-future`): ждёт событие и не прокачивает
  сообщения, поэтому вызывать только из фонового потока, не из UI-потока egui.
- На рабочем потоке перед WinRT нужен `CoInitializeEx(None, COINIT_MULTITHREADED)`
  (`Win32_System_Com`); результат можно игнорировать.
- DPAPI-блоб привязан к учётной записи и машине: копия сайдкара на другом ПК не
  разворачивается — это ожидаемо, а не баг.
- `aes-gcm 0.11` (aead 0.6): nonce — `Nonce<U12>` из `aes_gcm::aead::consts::U12`,
  `encrypt`/`decrypt` принимают `&Nonce`, ключ — `new_from_slice`.
- `hmac 0.13` / `sha1 0.11` / `sha2 0.11` (digest 0.11): `Hmac<D>::new_from_slice`,
  `update`, `finalize().into_bytes()`. Секреты TOTP — через base32 (`data-encoding`).
- `time 0.3`: `Date::parse` с `format_description!`; `to_julian_day()` возвращает i32
  (в разнице дней приводить к i64); `Month::length(year)` — длина месяца для срока карты.
- `cargo test -p vault-win` действительно вызывает DPAPI и проверяет раунд-трип —
  это единственный тест системных вызовов без GUI.
- **Копия файла в Проводнике — это не текст**: в буфере лежит список файлов
  (CF_HDROP), поэтому Ctrl+V в поле пути ничего не даёт. В 0.7.1 это решено
  кнопкой «Выбрать файл…» (`GetOpenFileNameW`), кнопкой «Вставить путь»
  (`GetClipboardData(CF_HDROP)` + `DragQueryFileW`) и перетаскиванием файла
  в окно (egui `raw.dropped_files`, путь берётся через `file.path()`).
- **Релизная сборка без консоли**: `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`
  в `main.rs`. Без него рядом с окном открывается консоль и забирает фокус с клавишами
  (именно так «не работал» F1). В debug-сборке консоль остаётся для логов.
- Системные диалоги `GetOpenFileNameW`/`GetSaveFileNameW` блокируют UI-поток —
  это нормально для модального окна; после возврата egui продолжает кадры.
- **Автоввод живёт на своём потоке**: `RegisterHotKey(None, ...)` + `GetMessageW`
  в отдельном std::thread (см. autotype.rs). Когда окно свёрнуто, eframe не вызывает
  `ui()`, поэтому печатать из UI-кадра нельзя — печать идёт в потоке горячей клавиши,
  а данные для неё лежат в `Mutex<Option<Credentials>>` (пароль — `Zeroizing<String>`).
- `SendKeys` в PowerShell НЕ вызывает зарегистрированные hotkey — для проверки
  использовать `keybd_event`/`SendInput`. Ввод идёт `SendInput` + `KEYEVENTF_UNICODE`,
  иначе кириллица и нестандартные раскладки не работают; в окна от администратора
  ввод блокируется UIPI (SendInput вернёт меньше событий).
- **Горячая клавиша перерегистрируется на лету**: `RegisterHotKey`/`UnregisterHotKey`
  работают только на своём потоке, поэтому перебиндинг идёт через `PostThreadMessageW`
  с `WM_APP+1` в поток клавиши (autotype.rs), а поток отвечает через канал — UI
  точно знает, встала ли комбинация. Если новая занята, старая возвращается на место;
  признак «работает» читается из `READY` каждый кадр, поэтому подсказка не врёт.
- **Запись сочетания в «Настройках»** берёт события `egui::Event::Key` и переводит
  `egui::Key` в виртуальный код Win32 только для букв, цифр и F1–F20. Пока идёт
  запись, F1/Ctrl+F/Esc/поиск не перехватываются, иначе сочетание нельзя было бы ввести.
- **Два экземпляра — источник путаницы**: RegisterHotKey держит только первая копия,
  а печатает та запись, что выбрана в ней. С 0.6.4 второй экземпляр берёт мьютекс
  `Hranitel.SingleInstance`, показывает MessageBox и выходит. Старые сборки (≤0.6.3)
  мьютекс не берут: если запущены и старая, и новая, Ctrl+Alt+P отработает старая.
  `CreateMutexW` требует `SetLastError(0)` перед вызовом — иначе `GetLastError`
  отдаёт сталый код и ложное срабатывание.
- **Дистрибутив в `dist/` собирается вручную**: копия `vault-win.exe`, `vault-cli.exe`,
  README и `docs` в `dist\Hranitel-<версия>-win64`, затем `Compress-Archive`. Старые пакеты
  не удаляются; если пользователь запускает вчерашний exe, он не видит новых функций.
  После изменений всегда пересобирайте пакет и давайте путь к самому свежему.

**Не коммитить**: `target`, `dist`, `*.opvault`, `*.vault`, `*.hello`, папку `NVIDIA Corporation`.

## 7. Ограничения текущей версии

- Нет синхронизации между устройствами и мобильного клиента.
- Расширение браузера: Chrome/Edge; Firefox (формат allowed_extensions) не
  поддерживается. Иконки в трее и passkeys нет.
- Windows Hello: только подтверждение присутствия, без TPM-привязки
  (доступность теперь проверяется при включении опции — Б-7 закрыта).
- Секрет TOTP не показывается в карточке, но доступен в диалоге правки —
  иначе не перенести код на другое устройство.
- 1Password 1PUX (архив) не читается, только CSV.
- CSV-экспорт теряет типы записей (документы уходят как логины); для полной копии — JSON.
- Автоввод: только логин/пароль выбранной записи и фиксированная последовательность
  (логин → Tab → пароль → Enter); отдельных сценариев под конкретные окна нет.
- Быстрый доступ и автоввод ищут главное окно по заголовку «Хранитель…» —
  не переименовывайте APP_TITLE без правки MAIN_TITLE_PREFIX в autotype.rs.
- Быстрая вставка понимает перечисленные форматы; пароль с пробелами внутри —
  только через строку «Пароль: …», иначе он делится на токены.
- Карты из Bitwarden CSV приходят без реквизитов (в CSV их нет).
- Лок файла мешает CLI при открытом GUI — осознанное поведение модели
  KeePass (задокументировано); синхронного просмотра в CLI нет.
- Словарь топ-10 000 — снапшот SecLists; обновляется пересборкой.
- Внешнего аудита не было.

### Этап 1. Windows Hello — сделано в 0.3.0

Реализовано по плану предыдущей передачи проекта: ключ хранилища обёрнут AES-256-GCM случайным
ключом обёртки, ключ обёртки — под DPAPI (область пользователя), сайдкар
`<файл>.hello` рядом с хранилищем; на входе — `UserConsentVerifier` в фоновом
потоке. Файлы: `crates/vault-core/src/hello.rs`, `apps/vault-win/src/hello_win.rs`,
UI — `main.rs`. Тесты: 10 на обёртку и 2 на DPAPI.

Что осталось по теме (не блокирует Этап 2):
- проверять доступность Hello (`CheckAvailabilityAsync`) при включении опции;
- TPM-привязка (сейчас только DPAPI user-scope);
- ручной прогон пунктов 11–14 чек-листа на машине с настроенным Hello.

Критерии приёмки (выполнены):
- Без включённой опции поведение не меняется.
- С включённой: запуск → Hello → хранилище открыто, мастер-пароль не спрашивается.
- Отказ или ошибка Hello → предложение ввести мастер-пароль.
- Смена пароля инвалидирует обёртку (сайдкар удаляется).
- Тесты на wrap/unwrap и на отказ при повреждённой обёртке.

### 0.8.2: путь к хранилищу и надёжный автоввод

- При открытии или создании хранилища путь пишется в `settings.txt` (`path=...`)
  и подставляется в поле при следующем запуске — длинный путь не нужно вводить заново.
- **Автоввод больше не теряет символы**: WM_HOTKEY приходит, когда Ctrl/Alt ещё зажаты,
  и SendInput в этот момент отдавал текст как сочетания — в чужом окне не появлялось
  ничего, хотя приложение сообщало «введено». Теперь перед печатью ждём отпускания
  Ctrl/Alt/Shift/Win (до 1,2 с) и только потом печатаем (autotype.rs).

### 0.8.1: смена сочетания без сюрпризов

- В «Настройках» сочетание записывается нажатием: «Записать сочетание» → нажать
  комбинацию целиком; текстовый ввод остался как запасной.
- Поток автоввода отвечает на перерегистрацию: если комбинация занята, остаётся
  прежняя, а диалог показывает причину (раньше старая снималась и автоввод

- Окно-мишень показывает сочетание из settings.txt (по умолчанию Ctrl+Alt+P),
  а не устаревшее Ctrl+Alt+A; подсказки в документации приведены к одному виду.

## 9. Правила проекта

- Интерфейс и документация — по-русски, код и идентификаторы — по-английски.
- Перед коммитом: `cargo fmt --all`, `cargo clippy -- -D warnings`, `cargo test --workspace`.
- Формат файла не менять без повышения `FORMAT_VERSION` и теста на старый файл.
- `vault-core` остаётся платформенно-независимым: никакого WinRT/DPAPI в ядре —
  эти вызовы только в `apps/vault-win` (ядро заберёт Android-клиент).
- Секреты не логировать, не печатать, не коммитить.
- Осмысленные сообщения коммитов по-русски.
