# Мост к браузеру (автозаполнение и сохранение паролей)

«Хранитель» — локальное хранилище без облака, поэтому интеграция с браузером
устроена по модели KeePassXC: расширение + родной хост + приложение. Так же
работают 1Password и Bitwarden, только у них вместо приложения — облако.

## Архитектура

```text
┌──────────────────┐  Native Messaging  ┌───────────────┐  named pipe   ┌────────────┐
│  Расширение      │ ◄──(stdio, JSON)─► │ browser-host  │ ◄────────────►│  Хранитель │
│  (extension/)    │                    │ (browser-host)│ \\.\pipe\...  │  (vault-win)│
└──────────────────┘                    └───────────────┘               └────────────┘
```

- **Расширение** (`extension/`, Manifest V3): показывает иконку в полях
  входа, запрашивает у приложения записи для текущего сайта, заполняет
  форму по клику, предлагает сохранить новый или изменённый пароль.
- **Родной хост** (`apps/browser-host`): крошечная программа без логики и
  без секретов. Браузер сам запускает её и общается по stdin/stdout;
  хост пересылает сообщения приложению по именованному каналу
  `\\.\pipe\hranitel-bridge`. Никаких сетевых портов.
- **Приложение** (`apps/vault-win`, модуль `browser.rs`): слушает канал,
  отвечает на запросы. Только оно знает мастер-ключ и хранилище.

## Протокол

Рамка сообщений — как в Native Messaging: 4 байта длины (little-endian) +
JSON. Действия — kebab-case.

| Запрос (расширение → приложение)            | Ответ (приложение → расширение) |
| ------------------------------------------- | -------------------------------- |
| `{"action":"ping"}`                          | `{"action":"pong","version":…}` |
| `{"action":"get-logins","url":…}`            | `{"action":"logins","items":[{id,title,username,url}]}` — без паролей |
| `{"action":"get-credentials","id":…,"url":…}`| `{"action":"credentials","username":…,"password":…}` |
| `{"action":"save-login","url","username","password","title"}` | `{"action":"saved","created":bool,"title":…}` |
| `{"action":"generate-password"}`             | `{"action":"password","value":…}` |
| ошибка на любом шаге                          | `{"action":"error","message":…}` |

## Модель безопасности

1. **Хранилище остаётся в приложении.** Расширение не читает файл и не
   получает мастер-ключ; пароли приходят по одному — ровно на клик
   пользователя по записи.
2. **Доступ по сайтам — с разрешением.** Первый запрос домена поднимает в
   «Хранителе» диалог: «Разрешить на этот раз / Всегда для домена /
   Отклонить». Постоянные разрешения лежат в
   `%APPDATA%\Hranitel\browser-sites.txt` (один домен в строке, можно
   править руками). Список записей отдаётся только после разрешения.
3. **Пароль по id — только своему сайту.** `get-credentials` проверяет,
   что запись действительно относится к адресу запроса (по базовому
   домену, см. `sites.rs`): фишинговая страница не получит пароль от
   настоящего сайта, даже зная id записи. Запрос без адреса (пустой или
   неразборчивый `url`) отклоняется целиком — и список, и пароль: иначе
   локальный процесс мог бы получить секрет, минуя диалог.
4. **Никакого автозаполнения при загрузке страницы.** Иконка в поле —
   по клику пользователя, как у 1Password и KeePassXC.
5. **Сохранение подтверждается в приложении.** Новый или изменённый
   пароль попадает в хранилище только после нажатия кнопки в окне
   «Хранителя» — доверенном интерфейсе, а не на веб-странице.
6. **Запросы будят окно.** Если «Хранитель» свёрнут, поток канала сам
   поднимает и разворачивает окно — вопрос не останется незамеченным.
7. **Один файл настроек.** Мост включается и выключается галкой в
   настройках (`browser=on/off` в `settings.txt`); при выключенном мосте
   расширение получает внятный ответ, а не тишину.
8. **Заблокировано — значит заблокировано.** При заблокированном
   хранилище любые запросы получают отказ; висящий в диалоге запрос
   тоже закрывается отказом.

## Установка (Chrome / Edge / Яндекс Браузер)

1. Соберите хост: `cargo build --release -p browser-host` (в готовом
   пакете `dist\Hranitel-<версия>-win64` уже лежат `browser-host.exe`,
   папка `extension` и `tools\install-browser-host.ps1` — собирать ничего
   не нужно).
2. Загрузите распакованное расширение: `chrome://extensions` →
   «Режим разработчика» → «Загрузить распакованное расширение» → папка
   `extension`. Скопируйте идентификатор (32 буквы).
3. Установите хост (без прав администратора). Проще всего — скрипт,
   который сам найдёт ID загруженного расширения (закройте браузер,
   чтобы профиль был записан на диск):

   ```powershell
   .\tools\install-browser-host-auto.ps1
   ```

   Вручную — с ID из карточки расширения:

   ```powershell
   .\tools\install-browser-host.ps1 -ExePath .\target\release\browser-host.exe `
       -ExtensionId <идентификатор> -Browsers chrome,edge
   ```

4. Запустите «Хранитель», откройте хранилище, откройте сайт из записей и
   щёлкните иконку замка в поле пароля. Первый раз подтвердите доступ.

Скрипт пишет манифест в `%APPDATA%\Hranitel\browser-host\ru.hranitel.bridge.json`
и два ключа реестра `HKCU\…\NativeMessagingHosts\ru.hranitel.bridge`.
Удаление моста — удалить ключи реестра и папку манифеста.

**Яндекс Браузер.** Он собран на Chromium и ищет родные хосты по ключу
Chrome — в `browser.dll` прописаны `SOFTWARE\Google\Chrome\NativeMessagingHosts`
и `SOFTWARE\Chromium\NativeMessagingHosts`. Отдельный ключ Яндекса не нужен:
достаточно `-Browsers chrome` (алиас `yandex` делает то же самое).
Расширение ставится так же: `browser://extensions` → «Режим разработчика» →
«Загрузить распакованное расширение»; ID показывается на карточке.
Если после создания ключа браузер уже был запущен — перезапустите его.

## Ограничения и планы

- Firefox использует формат `allowed_extensions` вместо
  `allowed_origins` — поддержим по запросу.
- Ассоциация расширения с приложением по общему секрету (как KeePassXC)
  появится позже: сейчас доступ контролируется браузером (запускать
  хост может только расширение с данным идентификатором) и разрешениями
  по доменам.
- Именованный канал с 0.13 создаётся с DACL «текущий пользователь и
  SYSTEM»: чужие учётные записи этой машины до него не достучатся. Любой
  процесс этой же учётной записи по-прежнему может отправить запросы
  напрямую — оттуда же берутся диалоги и разрешения по доменам. Подключения
  пишутся в журнал с PID и именем образа (диагностика, не защита).
  Общий секрет с расширением (как у KeePassXC) закроет и это — план 0.14.
- Поля с нестандартными фреймворками иногда не видят событий ввода —
  эвристика `setNativeValue` покрывает React/Vue, остальные будем
  добавлять по мере сообщений.
