## P0 — блокеры

### P0-1. Экспорт хранилища в GUI не работает никогда

`apps/vault-win/src/dialogs/export.rs:106` для подтверждения пароля делает `Vault::open(vault.path(), ...)`.
Но хранилище уже открыто и держит эксклюзивный лок `<файл>.lock` (`crates/vault-core/src/lock.rs:56-58`).
Повторное открытие в том же процессе упирается в собственную блокировку и возвращает `Error::Busy`,
а диалог показывает любую ошибку как **«Мастер-пароль неверен.»**

Проверено тестом: `AUDIT: повторное открытие отклонено: хранилище занято другим процессом ... v.opvault.lock`.

Пользователь видит: ввожу верный пароль — «неверен». Экспорт недоступен вообще.

**Исправление:** заменить `Vault::open` на `vault.verify_password(&self.export_password)`
(этот путь уже используется диалогом смены пароля, `dialogs/password.rs:130-134`, и в комментарии там
прямо написано, почему повторное открытие нельзя). Добавить регрессионный тест: экспорт при открытом хранилище.

### P0-2. В публичном репозитории лежит файл хранилища

`download/Хранилище` — 102 байта, первые 8 байт `OPVAULT1` → это файл хранилища (судя по размеру — пустое:
63 байта заголовка + 39 байт шифротекста). Файл **отслеживается git** (`git ls-files download` его показывает)
и добавлен коммитом `7d02eab` с сообщением-идентификатором `cc9d3fd1-...` — то есть попал туда автоматически,
вместе с `skills/` и `scripts/stub-bin/` (те уже удалены, файл остался).

Это нарушает собственные правила проекта (`.gitignore`: `/download/`, `*.opvault`, комментарий
«Хранилища паролей — в репозиторий не попадают никогда»). Прямой утечки нет (хранилище пустое),
но в истории git лежит рабочий файл, а сам паттерн «агент коммитит артефакты» опасен.

**Исправление:** `git rm --cached "download/Хранилище"`, затем чистка истории (`git filter-repo`/BFG),
pre-commit-хук, запрещающий файлы с сигнатурой `OPVAULT1` и каталог `download/`; проверить, не утекало ли
что-то ещё в коммитах того же автора.

## P1 — высокий приоритет

### P1-1. Счётчик «Аудит · N» не соответствует панели аудита

Тулбар считает `report.total()` — сумму **всех семи** категорий
(`crates/vault-core/src/audit.rs:76-84`: сроки, повторы, короткие, старые, пароль=логин, сайт в пароле,
словарный). Панель (`apps/vault-win/src/dialogs/audit.rs:41-70`) рисует только **четыре**: сроки, повторы,
короткие, старые. Три категории считаются, показываются в бейдже и **нигде не видны**.

Отсюда «Аудит · 658» при 401 записи: 658 — это находки, а не записи, и часть из них негде посмотреть.

**Исправление:** дорисовать три оставшиеся группы (данные уже есть в `AuditReport`), в бейдже показывать
«N записей / M находок», в панели — счётчики по категориям.

### P1-2. Автоввод печатает в любое активное окно и сам нажимает Enter

`apps/vault-win/src/autotype.rs:831` — после ввода логина и пароля безусловно отправляется `VK_RETURN`.
Проверки, что активное окно относится к выбранной записи, нет: есть только «это не наше окно»
(`autotype.rs:846-852`). Сценарии: фокус в чате/терминале/поисковой строке → пароль уходит туда,
а Enter в терминале **выполняет команду**.

**Исправление:** перед вводом сверять заголовок окна (или URL браузера через `uia`) с доменами записи
(есть готовый `Item::url_match_strength`), опция «не нажимать Enter», отмена по Esc во время ввода.
Минимум — не отправлять Enter для окон, не похожих на форму входа.

### P1-3. Расширение показывает сгенерированный пароль открытым текстом

`extension/content.js:244`: `toast(\`Пароль сгенерирован: ${password.value}\`)` — пароль на 3,5 секунды
виден на странице (демонстрация экрана, скриншот, запись). Для менеджера паролей это лишняя утечка.

**Исправление:** «Пароль вставлен в поле» без значения.

### P1-4. TOTP-поле может полностью исчезнуть из карточки

Карточка рисует TOTP-блок только при успешном `Totp::parse` (`ui/main_view.rs:836-848`), а само поле
исключается из таблицы по сравнению указателей (`ui/main_view.rs:1006-1010`). Если значение не разобралось
(подпись «TOTP», а значение — не base32, битая ссылка `otpauth://`), секрет **не показывается нигде**,
кроме диалога правки. Данные целы, но выглядят потерянными.

**Исправление:** при ошибке разбора показывать поле обычной строкой + пометку «не разобран TOTP».

### P1-5. Параметры KDF из файла не ограничены сверху

`crates/vault-core/src/crypto.rs:48-63`: проверяется только минимум (`m_cost ≥ 8 МиБ`), `t_cost` — без верхней
границы. Подменённый файл с `t_cost = 10^9` подвесит разблокировку на часы (отказ в обслуживании),
`m_cost` в гигабайты — упирается в аллокацию.

**Исправление:** клампы `m_cost ≤ 1 ГиБ`, `t_cost ≤ 64`, `p_cost ≤ 16` с внятной ошибкой.

## P2 — средний приоритет

1. **Один флаг «Показать» на всё.** `state.rs:279,351-367`: раскрывает и пароль, и все чувствительные поля
   сразу; сбрасывается только кликом по строке (`main_view.rs:771`), не сбрасывается при смене выбора из
   аудита, undo, сохранения. Нужна видимость per-field и сброс в `set_selected`.
2. **Панель аудита считает отчёт каждый кадр.** `dialogs/audit.rs:12` → `vault.audit()`, а группировка
   повторов — линейный поиск по списку, O(n²) (`audit.rs:129-146`). 400 записей × 60 fps ≈ 4,8 млн сравнений/с.
   Нужен кэш по `vault.revision()` — механизм уже есть в `audit_total` (`state.rs:1157-1167`)
   или `HashMap`-группировка.
3. **Каждый кадр — клон записи с секретами.** `main_view.rs:805` (`...cloned()`), плюс поиск и счётчики
   категорий по всем записям каждый кадр (`main_view.rs:543-660`). На 400 записях терпимо, на 10 000 — лаги.
4. **Импорт в UI-потоке.** `main_view.rs:472`: `import_file(...)` синхронно в кадре — окно замирает без
   прогресса на больших файлах. Нужен фон + прогресс/отмена.
5. **Дублирование домена в списке.** `main_view.rs:673`: подзаголовок всегда «логин · домен», даже когда
   заголовок записи уже равен домену. Это ровно то, что видно на скриншоте: `1capp.com` / `Администратор · 1capp.com`.
   Не добавлять домен, если он совпадает с заголовком; при импорте строить заголовок из `name` + логина,
   если `name` — голый домен.
6. **Карточка записи без заполненных полей выглядит сломанной.** `main_view.rs:1011-1013` пропускает пустые
   поля; API-ключ «222» даёт пустую правую панель. Показывать шаблонные поля с «—» и подсказкой
   «Заполнить — Изменить», либо empty-state.
7. **Выбранная запись может быть вне экрана.** Автоскролла к выбранной строке нет; на скриншоте выбран «222»,
   а список показывает начало — кажется, что ничего не выбрано.
8. **CSV-инъекция.** `crates/vault-core/src/export.rs:70-101`: значения, начинающиеся с `=`, `+`, `-`, `@`,
   Excel/LibreOffice исполнят как формулу. Известный класс утечек в менеджерах паролей. Экранировать префиксом.
9. **Экспорт пишет файл без ограничения прав и не атомарно.** `dialogs/export.rs:113`: `std::fs::write`,
   права наследуются от каталога — открытые пароли читаемы другими пользователями/процессами.
   Использовать `write_atomic` + DACL «только владелец» + кнопку «Удалить файл сейчас».
10. **Буфер обмена и история Windows.** `state.rs:882-894`: автоочистка через 30 с есть, но значение попадает
    в историю Win+V и облачную синхронизацию и там остаётся. При копировании выставлять форматы
    `ExcludeClipboardContentFromMonitorProcessing` / `CanIncludeInClipboardHistory = 0`.
11. **Мост: подлинность клиента не проверяется.** DACL канала, диалоги и разрешения по доменам — хорошо
    (`browser.rs:143-190`), но любой процесс той же учётной записи может подключиться к
    `\\.\pipe\hranitel-bridge` и запросить записи для уже разрешённого домена. В README это признано,
    общий секрет обещан в 0.14 — это стоит ускорить (HMAC над запросом), а до тех пор показывать в логе
    предупреждение о подключении не-`browser-host` (уже есть) и требовать подтверждения на каждый
    `get-credentials`, а не только на новый домен.
12. **Windows Hello защищает от соседа, но не от кода в сессии пользователя.** `hello_win.rs:143`:
    DPAPI-блоб разворачивается без участия человека, Hello-подтверждение — отдельный шаг приложения.
    Вредоносный процесс в сессии пользователя расшифрует сайдкар и откроет хранилище без Hello.
    Это ограничение схемы; его надо честно описать в справке/README, чтобы не создавать ложного ощущения защиты.
13. **«Hello: вкл/выкл».** `main_view.rs:160-162`: непонятная подпись (это Windows Hello) и выключение
    без подтверждения. Писать «Windows Hello: включён», выключение — с подтверждением.

## Что сделано хорошо (чтобы не потерять при переделке)

- Криптография: Argon2id + XChaCha20-Poly1305, заголовок под AAD, соль/nonce из ОС, параметры KDF в файле с проверкой минимума.
- Запись файла: tempfile → `sync_all` → `persist`, `.bak` перед каждой записью, файловый лок, атомарный сайдкар Hello.
- Секреты: `Zeroizing`/`zeroize` в ключевых местах, `Debug` без секретов, лог без названий и паролей.
- Мост: DACL канала «пользователь + SYSTEM», лимит сообщения 1 МиБ, белый список действий, разрешения по доменам,
  `get-credentials` проверяет принадлежность записи сайту.
- Тесты: 157 проходят, включая векторы RFC 6238, golden-совместимость формата, порчу шифротекста, подмену KDF,
  рамку native messaging; CI с `clippy -D warnings`, `cargo audit`, кросс-таргетом.
