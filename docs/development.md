# Как работать с проектом

Памятка для себя: всё простыми словами. Проект лежит в `E:\Work\VSC\POSPassword`.

## 1. Что установлено

- **Rust** (`cargo`, `rustc`) — на нём написаны и ядро, и приложение.
- **VS Code** — редактор. Настройки проекта лежат в папке `.vscode`.
- **Git** — сохранение версий и отправка на GitHub.

Проверить, что всё на месте:

```powershell
cargo --version
git --version
```

## 2. Первый запуск

1. VS Code → «Файл» → «Открыть папку» → `E:\Work\VSC\POSPassword`.
2. Справа внизу VS Code предложит установить расширения — нажмите «Установить».
   Нужны три: rust-analyzer (подсказки и проверка кода), C/C++ (отладчик), TOML.
3. Нажмите `Ctrl+Shift+B` — проект соберётся. Первая сборка долгая (2–3 минуты),
   потому что скачиваются и компилируются библиотеки. Дальше — секунды.
4. Нажмите `F5` — откроется окно «Хранитель».

## 3. Задачи (кнопки)

`Ctrl+Shift+P` → «Задачи: Выполнить задачу» → выберите нужную:

| Задача | Что делает |
|---|---|
| Сборка (debug) | Компилирует всё. Ошибки подсвечиваются в коде. |
| Тесты | Прогоняет все тесты workspace: ядро, импорт, шаблоны, Windows Hello. |
| Запуск приложения | Собирает и открывает окно. |
| Запуск CLI | Спрашивает аргументы и запускает командную строку. |
| Сборка релиза | Оптимизированная версия в `target/release`. |
| Проверка clippy | Ищет сомнительные места в коде. |
| Проверка типов | Быстрая проверка без сборки. |
| Форматирование | Приводит код к единому виду. |
| Всё перед коммитом | Форматирование + clippy + тесты одной кнопкой. |

`Ctrl+Shift+B` — это сразу «Сборка (debug)». `F5` — сборка и запуск под отладчиком:
можно ставить точки останова (клик слева от номера строки) и смотреть значения переменных.

## 4. Где что менять

- **Шифрование и формат файла** — `crates/vault-core/src/crypto.rs` и `vault.rs`.
  Менять формат без версии нельзя: старые файлы перестанут открываться.
- **Поля записи, поиск** — `crates/vault-core/src/model.rs`.
- **Генератор паролей** — `crates/vault-core/src/generator.rs`.
- **Окно приложения** — `apps/vault-win/src/main.rs`.
- **Команды CLI** — `crates/vault-cli/src/main.rs`.

После изменения ядра обязательно запустите «Тесты».

## 5. Сохранение версий

Обычный порядок:

```powershell
git status                     # что изменилось
git add -A                     # подготовить все изменения
git commit -m "кратко: что сделано"
git push                       # отправить на GitHub
```

Если Git просит имя и почту:

```powershell
git config --global user.name "reznikov73"
git config --global user.email "reznikov_a@mail.ru"
```

Коммитить лучше после того, как «Всё перед коммитом» прошло без ошибок.

## 6. Если что-то не работает

- **Подсказки в коде не появляются** — подождите: rust-analyzer первый раз индексирует
  проект минуту-две. Если не помогло: `Ctrl+Shift+P` → «Rust Analyzer: Restart server».
- **Сборка падает с «Access denied»** — запущено старое окно приложения. Закройте его
  и соберите снова.
- **Кракозябры вместо русских букв** — проверьте, что файл сохранён в UTF-8
  (внизу справа в VS Code должно быть «UTF-8»).
- **Долгая сборка** — первый раз это нормально. Папку `target` не удаляйте без нужды:
  после её удаления всё компилируется заново.
