«Хранитель 0.13.0» — светлый интерфейс (макет A) + усиление безопасности
Проект: POSPassword / «Хранитель»  ·  Репозиторий: github.com/reznikov73/POSPassword
Базовая версия: 0.12.3  ·  Целевая: 0.13.0  ·  Дата: 18.11.2026  ·  Статус: правки ревью внесены — к реализации
Основание: ревью проекта 0.12.3; принят макет A «Эволюция текущего» (светлый, две колонки).
Ревизия: правки по итогам технического ревью ТЗ от 18.11.2026 (пункты Б-1, Б-3а, Ф-5, Ф-6, И-4, И-6, И-7, И-9, Т-2, Т-3, Т-4 — отмечены [р]).

1. Цель и принципы

Цель: эволюция главного окна без слома привычек пользователя, закрытие дыр безопасности P0, подготовка кодовой базы к росту.

  • Офлайн, один файл, без аккаунтов и сети.
  • FORMAT_VERSION = 1 не меняется; новые поля — только через serde(default).
  • vault-core платформенно-независим; все Win32/WinRT — в apps/vault-win.
  • UI и документация — по-русски, код — по-английски; осмысленные коммиты по-русски.
  • Перед коммитом: cargo fmt --all, cargo clippy -- -D warnings, cargo test --workspace.
  • egui/eframe 0.37; новые зависимости — только лёгкие и офлайн (idna, встроенный PSL).
  • Секреты не логировать, не печатать в Debug, занулять.

2. Объём работ

Входит

Интерфейс по макету A; избранное; история пароля; undo удаления; напоминания о сроках; резервные копии; аудит+; безопасность P0 (PSL/IDN, буфер/zeroize, мастер-пароль, Argon2-пресеты, Hello, DACL канала); разрезание main.rs; CI; документация.

Не входит (следующие релизы / отдельные ТЗ)

Полная ассоциация расширения по секрету (0.14); TPM-привязка Hello; per-item сценарии автоввода; Firefox; корзина и сайдбар (макет B); дашборд (макет C); синхронизация; Android; passkeys; HIBP-проверка (нарушает офлайн-принцип — на обсуждение).

3. Макет и общие требования к интерфейсу

Зоны главного окна сверху вниз: titlebar (версия + путь) → тулбар → чипсы категорий → контент: список слева / карточка справа → статус-бар.

Рис. 1 — Структура главного окна по макету A (схема зон).
  • Светлая тема — по умолчанию для новых установок; layout идентичен в тёмной и контрастной темах.
  • Минимальный размер окна 760×520: чипсы переносятся, карточка скроллится, кнопки не наезжают на путь.
  • Обязательные состояния: пустое хранилище, ничего не найдено, запись не выбрана, аудит = 0 («Аудит ✓»), буфер занят (обратный отсчёт).
  • Все действия доступны с клавиатуры; подсказки хоткеев — в статус-баре и hover.

4. Требования к интерфейсу (И)

IDТребованиеКритерий приёмки
И-1Тулбар по макету: слева «+ Запись», «Генератор», «Быстрая вставка», «Импорт…», «Экспорт…»; справа «Аудит · N» (янтарный при N>0, зелёный «✓» при 0), Hello, «Заблокировать», ⚙, «Справка F1». «Описания», «Пароль», «Тема» — в меню ⚙.Все текущие функции достижимы ≤ 2 клика; счётчик аудита обновляется после каждого сохранения.
И-2Чипсы: Все / Логины / Карты / Счета / Заметки / Документы / Ключи + «★ Избранное», у каждого — счётчик; активный залит акцентом; работают вместе с поиском.Ctrl+1…7 переключают категории, Ctrl+8 — избранное; счётчики совпадают со списком.
И-3Строка списка: аватар-буква типа, название, подзаголовок «логин · сайт» (или тип), badge справа: TOTP (зелёный), срок ≤90 дн (янтарный) / просрочен (красный), ★; выделение — акцентная полоса + мягкая заливка.Badge видны без открытия карточки; контекстное меню ПКМ: Изменить / Копировать логин / Копировать пароль / В избранное / Удалить.
И-4Карточка: кнопка копирования у каждого поля; пароль — маска + «Показать» + копирование + шкала стойкости (5 сегментов, биты, вердикт); TOTP-блок: код «XXX XXX», кольцо обратного отсчёта, кнопка «Код» (секрет не показывается в карточке, но остаётся доступным в диалоге правки — сценарий переноса кода на другое устройство [р]); «Ещё сайты» и теги — чипсами; даты; внизу «Ввести в окно · 3 с».Код и кольцо обновляются раз в секунду; копирование кода — в буфер с 30-с очисткой; шкала совпадает с password_entropy_bits.
И-5«История пароля: N версии» — раскрываемый блок: дата, маска, копирование, «Сделать текущим».Восстановление версии меняет пароль, прежний текущий уходит в историю, файл сохраняется.
И-6Undo удаления: после «Удалить» — toast «Запись удалена · Вернуть» на 10 с. Undo-буфер сбрасывается при lock() [р].«Вернуть» возвращает запись с тем же id, датами и полями; по таймауту и при блокировке буфер зануляется.
И-7Окно запоминает размер и позицию (size=, pos= в settings.txt), при восстановлении — clamp к экрану. Геометрия пишется только из нормального видимого состояния: скрытое в трей окно (позиция −32000, WS_EX_TOOLWINDOW) и развёрнутое на весь экран состояние не перезаписывают сохранённые значения [р].После перезапуска окно там же и того же размера; за пределами экрана не появляется; после «скрыть в трей → выйти» окно при следующем запуске возвращается на прежнее место.
И-8Статус-бар: «Записей: N», обратный отсчёт буфера, подсказки хоткеев (сохранить текущее поведение).Подсказка автоввода не врёт после смены сочетания.
И-9Напоминание при разблокировке: если есть истекающие ≤30 дн / просроченные — toast «Истекает: N → Аудит», клик открывает аудит. Порог напоминания (30 дн) — мягче, чем у списка «истекающие» в аудите (90 дн): о ближней границе сообщаем лично, дальнюю видит тот, кто сам открыл аудит. Оба числа фиксированы и задокументированы [р].Показывается один раз за разблокировку; при нуле — не показывается.
И-10Пустые состояния по п. 3.Каждое состояние отрисовано и не выглядит как ошибка.

5. Функциональные требования и данные (Ф)

IDТребованиеКритерий приёмки
Ф-1Item.favorite: bool, serde(default); звезда в карточке/списке/контекстном меню; фильтр «Избранное».Старые файлы читаются без миграций; round-trip через файл сохраняет флаг.
Ф-2Item.password_history: Vec<PasswordVersion { value, changed_at }>, ≤5, serde(default); запись при смене пароля (старый непустой → в историю с прежней датой); Drop зануляет значения.История не растёт выше 5; смена пароля через GUI/CLI/мост пишет историю одинаково.
Ф-3Аудит+: пароль = логин; пароль содержит имя сайта/домен; офлайн-словарь топ-10 000 паролей (встроен в бинарник). В отчёте — только факт, не значение.Новые группы находок с тестами; словарь не индексируется поиском и не попадает в экспорт.
Ф-4Палитра Quick Access: Ctrl+T — копировать TOTP выбранной записи; badge TOTP в строке (опционально: fuzzy-поиск).Ctrl+T работает только при открытом хранилище; код очищается из буфера через 30 с.
Ф-5Резервные копии: автоматический <файл>.bak (предыдущая версия, одно поколение) при каждом save — обновляется копированием до атомарного переименования (без окна, в котором основного файла нет [р]); кнопка «Резервная копия…» → копия vault-ГГГГ-ММ-ДД.opvault через системный диалог. *.bak — в .gitignore [р]..bak открывается как обычное хранилище; ручная копия побайтово равна исходнику.
Ф-6Защита от параллельной записи (GUI + CLI), модель KeePass [р]: сайдкар-лок <файл>.lock с ОС-блокировкой (flock/LockFileEx, освобождается при смерти процесса); GUI держит лок от открытия хранилища до блокировки/закрытия, CLI — на всё время команды. Это закрывает не только повреждение (его и так гарантирует атомарный rename), но и потерю правок (lost update) вторым писателем.Второй писатель получает внятную ошибку «хранилище занято» (GUI-приложение открыто или работает CLI), файл не повреждается и правки не теряются; упавший процесс не оставляет вечного лока.
Схема данных: VaultData.schema: 3 → 4. Формат файла не меняется. Старое приложение новые поля игнорирует, но при сохранении из старой версии они теряются — зафиксировать в docs/transfer.md и README («обновляйте все копии»).

6. Требования безопасности (Б)

IDТребованиеКритерий приёмки
Б-1Полный PSL (включая приватные зоны github.io, herokuapp.com…) вместо списка из 49 суффиксов. Способ встраивания [р]: снапшот официального списка в репозитории (include_str!), парсинг при первом обращении (OnceLock); рост бинарника ~250–300 КБ — принято. Обновление — регенерацией снапшота скриптом в tools/ (частота — по мере выхода версий, деградации нет: старый список консервативен). Неизвестный TLD — по правилу PSL (неявная «*»): регистрируемый домен = последние две метки. Точный хост совпадает всегда.Векторы: bank.co.il ≠ evil.co.il, userA.github.io ≠ userB.github.io, lk.domclick.ru = domclick.ru — тесты.
Б-2IDN → punycode в normalize_host; в диалоге разрешения домен показывается и в punycode.Омограф е/e не матчится как тот же сайт; тест.
Б-3aDACL именованного канала — только текущий пользователь (+ SYSTEM): это и есть защита. Проверка PID клиента (GetNamedPipeClientProcessId → имя образа) — диагностика, а не граница защиты [р]: PID и путь образа пишутся в лог для разбора инцидентов; отклонять по имени образа нельзя (легальный путь установки произволен, имя подделывается). Б-3b (полная пара по секрету) — 0.14, отдельное ТЗ.Чужой пользователь не подключается (DACL); каждое подключение отражается в логе с PID и образом, без секретов.
Б-4Буфер очищается сразу при lock(), если там наш секрет; UI-копии секретов (Draft.password, строки палитры, undo-буфер, App.clipboard) — Zeroizing/зануление.Тест: после блокировки буфер пуст; секреты не живут в куче после закрытия диалога.
Б-5Индикатор стойкости мастер-пароля при создании и смене (биты + вердикт + предупреждение по словарю); минимум 8 символов сохраняется, жёсткого запрета нет.Индикатор переиспользует password_entropy_bits; словарное предупреждение срабатывает на «password123».
Б-6Пресеты Argon2 при создании/смене: «Стандарт» 64 МиБ/t3 (без изменений), «Усиленный» 128 МиБ/t4, «Максимальный» 256 МиБ/t4; параметры — в заголовке, апгрейд при смене пароля.Старые файлы открываются; новые параметры пишутся и проверяются AAD; время разблокировки замерено и указано в подсказке.
Б-7Hello: CheckAvailabilityAsync при включении опции; при недоступности — внятный отказ, опция не включается.На машине без Hello кнопка сообщает причину и не создаёт сайдкар.

8. Нефункциональные требования (Н)

  • Разблокировка ≤ 0,5 с на стандартном пресете (эталонный ПК); усиленные пресеты — с предупреждением о времени.
  • 1000 записей: поиск и отрисовка списка ≤ 50 мс; образец фразы не пересоздаётся каждый кадр (регресс 0.9.1 закрыт тестом).
  • Никаких сетевых вызовов; новые зависимости — только офлайн и лёгкие.
  • Секреты: не в логах, не в Debug, зануление при уничтожении.
  • Совместимость: FORMAT_VERSION = 1, schema 4, старые файлы без миграций.
